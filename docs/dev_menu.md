# Dev menu and Report

**Opening it.** Only with `?dev` in the page address (a DEV button top-right, and the build stamp bottom-left), or five quick taps on the "build abc1234" tag (main menu or pause screen) in any build. Nothing of it exists otherwise: no node, no button (`Main.dev_menu` stays null; the smoke test checks it). The tap count resets after 0.9 s without a tap. It pauses the game behind it; Close resumes.

**Career tab.** Presets set the whole save to where the average bot is (docs/content_audit.md 10.2, 11.1): airport k opens at 0, 2.1, 5.7, 8.7, 11.9, 15.2 h (level 8 of the one before), level 8 when the next airport opens, level 20 at 67 h; stars 1/2/3 at level 2/6/12; mastery landings = 0.15 x XP; improvements and tower upgrades bought cheapest-first with a share of their total price (hours / 60), shop cosmetics with hours / 10; about four unit-pays in the bank; every tip counts as seen. Presets: Fresh start (a new save, Day 1 on), 30 min, 2 h (County just opened), 10 h, 30 h, 60 h, Everything done. It is a model of the bot, not a replay of one (the bot is not run), so a preset's purchases are where the average bot would be within a few levels. Manual: +1,000, +10,000, unlock all airports, a level per airport (-, +, 20).

**Scenario tab.** Airport, then any mix of: a student arrival at 3 s (needs a legal end: with the forced crosswind none is sent, as in the game), wind (calm: end 0 of the main runway is into the wind; crosswind: as far off the runway as the wind still allows; from behind: the usual end is closed and the far end takes the traffic; each holds steady for the shift), weather at 3 s (gusty crosswind needs 2+ runways, storm, fog), a challenge (Bad Pilot Day, No engines), a weekly event forced on (any of the five), heavy traffic (arrivals 2.5 x as often), near-full hangar (the hangar and the score are two landings from full; the parked planes' pictures come with the next landings).

**Time tab.** Game speed x1 / x2 / x4 (that many steps of the normal size per frame, never one big step; the DEV button shows the speed). Skip to results with a poor (0 stars), average (1), good (2) or 3-star score: from a menu it first starts a shift at the Scenario airport. Away 1 / 8 / 24 h: sets the offline clock and shows the welcome-back screen. Advance one day / back to today (daily goals, streak and the weekly event follow the day number), reset daily goals.

**Save tab.** Export puts a code (`PW1.<size>.<deflated JSON in base64>`, about 1.4k characters late in the game) in the box and on the clipboard; Import reads the box (stray spaces and line breaks are fine; a bad code changes nothing). Three checkpoints are kept on the device (`user://dev_checkpoint_N.txt`).

**Report a problem** (pause menu, for everyone). Copies a text block: build, device, screen size, airport and level, coins, shifts, stars, the screen, the shift's state, the last 20 game events (landings, go-arounds, fines, wind and weather, purchases, menus). The screenshot is of the screen as it is when the button is tapped (the pause menu is over it): on the web it downloads as a picture file (a picture cannot go in text), elsewhere it is saved in the app's folder and its path is in the block. The pause title says "REPORT COPIED" for 2.6 s.

**Checks.** `tools/ui_overlap_check.gd` pictures the four tabs at every size ("Dev menu" group in the gallery) and measures them at 390 x 844 (nothing off-screen, no overlapping buttons, text inside its button, every button a finger tall). They are not among the player states. The smoke test (section 49) covers presets, the save code round trip, every scenario, speed, skip, offline, the day, the report and the five taps.
